# 历史净值缓存与交易变更的一致性

本次修复交易新增、修改、删除后业绩仍读取旧净值，以及无交易区间无法强制重算的问题。

## 缓存失效

- 交易变更与日度缓存清理放在调用方的同一个 SQLite 事务中。
- 新增、删除从交易日期起清理；修改从旧日期、新日期中较早的一天起清理。
- 同时清理 `daily_portfolio_values` 与 `daily_holding_snapshots`。
- 日期统一使用 SQLite `DATE()` 的 UTC 语义；无法解析的旧日期按全区间失效处理。
- 只修改交易名称、备注时保留日度缓存。
- 导入、撤销导入与期初持仓编辑复用相同的日期归一化和清理服务。

## 读取与刷新

- 进入业绩页仍然按需补齐缓存，显式刷新则重算所选区间，不再要求区间内有交易。
- 回填包括所选区间之前的一个工作日，供区间收益使用正确的期初净值。
- 真正没有持仓的日期清除旧缓存；零现金余额允许保存为零。
- 明确的历史行情请求错误中止回填，不覆盖已有缓存；成功返回空行情时保留原有的新股成交价回退逻辑。
- 刷新错误显示在业绩页。同一范围刷新失败可保留上次完整报告；范围变化后不沿用旧范围的报告。

## 并发与迁移

数据库 v7 增加单调修订号。交易、持仓的相关变更通过数据库触发器更新修订号；回滚也会回滚修订号。回填在读取持仓时记录修订号，在最终写入事务内再次核对。如果行情请求期间账本已变化，返回重试提示，避免将过期计算重新写入缓存。

升级时一次性清理旧版可能已失真的两张日度缓存表，下次查看业绩时重建。交易、持仓、导入审计、季度快照及复盘笔记保持原样。

## 验证边界

回归使用内存或临时数据库、固定行情和汇率，覆盖交易补录、日期/费用修改、末笔删除、备注修改、失败回滚、跨时区导入撤销、无交易强制刷新、空持仓、行情失败、并发变更、迁移幂等性及前端请求顺序。开发验证不操作用户数据库。

本次不调整历史汇率和成本估算口径、季度复盘口径或证券标识结构。

# 股票操作复盘旧引擎退役设计

## 背景

股票操作复盘已经切换为轻量版：从交易记录重放建仓、加仓、减仓和清仓，评价每项操作截至复盘期末对组合的价格影响，并与所属市场基准比较。组合收益、最大回撤、影子组合、风险结构和 Campaign 等能力与绩效分析重复，同时使复盘依赖现金、汇率、交易日历、完整行情和组合曲线，产生了大量与操作评价无关的不可用状态。

当前代码库仍保留旧复杂引擎、人工纠错、复盘注释、交易日历缓存、旧前端组件、旧命令和相关数据模型。轻量服务也仍通过旧动作构建器读取纠错记录。继续保留这些依赖会让两套事实口径并存，并增加维护和误调用风险。

本次清理采用一次性干净切换：股票操作复盘的确定性结果只由原始交易记录及只读市场数据计算，不再接受人工或 AI 对交易事实的覆盖。

## 目标

1. 删除股票操作复盘旧复杂引擎及其完整依赖闭包。
2. 取消所有人工纠错、注释回写和 AI 修改复盘事实的能力。
3. 新建或重构最小原始交易动作构建器，不依赖任何旧复盘模型或持久化数据。
4. 保持现有轻量版页面、轻量报告接口和只读 AI 深度复盘可用。
5. 新数据库不再创建旧纠错、注释和交易日历表；已有数据库中的旧表保持惰性兼容，不读、不写、不迁移、不自动删除。
6. 通过编译、测试、生产构建和源码审计证明旧能力没有可执行残留。

## 非目标

- 不恢复组合 TWR、累计收益、最大回撤或风险结构；这些能力继续由绩效分析负责。
- 不实现 Campaign、MAE/MFE、固定观察窗口或交易日级深度归因。
- 不提供旧纠错数据迁移到新模型的通道。
- 不自动删除现有用户数据库中的历史纠错、注释或日历表。
- 不让 AI 根据用户描述改写原始交易记录或确定性指标。
- 不改变期权操作复盘、持仓复盘和绩效分析的业务边界。

## 唯一事实来源

股票操作复盘以交易表中的原始记录为唯一交易事实来源。服务按账户、标准化市场、标准化股票代码和成交时间排序，重放查询结束日前的完整交易历史，并从查询区间内的买卖记录生成操作。

计算过程中不得读取下列旧数据：

- `stock_review_overrides`
- `stock_review_annotations`
- `stock_market_sessions`
- `stock_market_calendar_coverage`

也不得通过其他缓存、AI 输出或用户注释修改成交方向、数量、价格、费用、股票、账户或成交时间。

行情与汇率只用于给原始操作估值，不改变交易事实。行情缺失采用字段级降级，不触发交易纠错。

## 最小计算链路

```text
原始交易记录
  -> 规范化账户、市场和股票代码
  -> 按时间重放持仓股数
  -> 合并同账户、同股票、同交易日、同方向成交
  -> 生成 open / add / reduce / close 操作
  -> 获取操作日至复盘期末的股票端点行情
  -> 获取所属市场基准端点行情
  -> 读取操作前最近的组合资产快照与必要汇率
  -> 计算价格效果、相对基准效果和估算仓位变化
  -> 输出概览、股票排行和操作明细
```

该链路不构建完整组合收益曲线，不依赖复盘专用交易日历，也不生成影子组合、Campaign 或全局可用性结论。

## 原始交易动作构建器

旧 `stock_action_builder` 同时承担纠错覆盖、转仓确认、问题报告、观察窗口和旧报告模型构造。它将被删除或收缩为不依赖旧模型的最小构建器。

最小构建器只输出轻量计算需要的事实：

- 操作 ID 和组成交易 ID。
- 账户、市场、股票代码和名称。
- 操作日期与方向。
- `open`、`add`、`reduce`、`close` 类型。
- 成交股数、金额加权均价、成交金额、费用和币种。
- 操作前后股数。

构建规则：

1. 使用查询结束日前的全部相关交易重放股数，只输出查询区间内的操作。
2. 同账户、同股票、同一自然交易日、同方向的成交合并为一项操作。
3. `BUY` 增加股数，`SELL` 减少股数；卖出不得把内部重放股数降到零以下。
4. 现金、分红、拆股和合成期初等非买卖记录不生成可评价操作，但仍按交易模型已有语义参与必要的股数重放。
5. 不再识别或确认“转仓纠错”。如果原始记录是买卖，就按买卖评价；如果原始交易类型不是买卖，就不生成操作。
6. 不产生旧版问题、纠错建议、事实覆盖、Campaign 事件或前瞻观察窗口。

## 保留的代码边界

后端保留并清理：

- `stock_operation_review` 轻量模型。
- `stock_operation_review_service` 轻量查询与编排。
- `stock_operation_review_calculator` 纯计算逻辑。
- 原始交易动作构建器。
- 轻量端点行情加载与 `stock_daily_prices` 缓存。
- `get_stock_operation_review` Tauri 命令。
- AI 只读 `get_stock_review` 工具，其返回值直接来自轻量服务。

前端保留：

- 轻量筛选器和股票复盘页签。
- 四张轻量概览卡片。
- 股票操作效果排行。
- 操作明细。
- 字段级质量摘要。
- 轻量股票操作复盘状态管理和视图模型。
- “请 AI 深度复盘”入口。

## 删除的旧依赖闭包

后端删除：

- 旧股票复盘服务及大型旧报告模型。
- 影子组合、调仓归因、Campaign、旧指标和旧质量判定模块。
- 复盘专用权威交易日历和覆盖率模块。
- 纠错、注释和旧报告持久化模块。
- 旧股票报告、Campaign 详情、保存注释和确认纠错命令。
- AI 保存复盘注释或纠错的工具定义、处理器、权限声明和测试。
- 只为旧报告服务的问答压缩、问题选择和响应策略代码。
- 上述模块的单元测试、集成测试和测试夹具。

前端删除：

- 旧股票复盘面板。
- 实际/影子/基准组合图表。
- 调仓归因、风险结构、Campaign 抽屉和旧操作表。
- 旧数据质量、旧概览卡片和旧视图模型。
- 旧股票复盘状态管理。
- 旧报告、纠错、Campaign 和注释类型。
- AI 保存注释工具的展示名称、工具卡片映射和测试夹具。

文档删除或更新：

- 删除已经被轻量版取代的旧复杂引擎设计、计划和交易日历验证文档。
- 更新轻量版设计中“暂时保留旧引擎”的过渡描述。
- 保留与期权操作复盘、绩效分析及其他功能有关的文档。

## 数据库兼容策略

新数据库只创建当前仍使用的 `stock_daily_prices` 行情缓存，不再创建、迁移或索引旧复盘表。

对于已存在的用户数据库：

- 不执行 `DROP TABLE`。
- 不读取、写入或迁移旧表。
- 重置复盘缓存时不再操作旧表。
- 旧数据对任何新报告、页面和 AI 回答均无影响。

该策略让代码和运行时行为彻底退役旧能力，同时避免在应用升级时不可逆删除用户历史数据。未来如确需物理清除，应设计为用户明确触发的独立维护动作，而不是隐式迁移。

## API 与 AI 行为

页面继续只调用 `get_stock_operation_review`。旧命令从 Tauri 注册表和命令实现中移除，不保留兼容壳；任何未迁移调用会在编译、测试或运行时立即暴露，而不是悄悄回退到旧引擎。

AI 继续通过只读 `get_stock_review` 取得与页面相同的轻量报告。AI 可以：

- 总结影响最大的正向和负向操作。
- 比较买入/加仓与减仓/清仓效果。
- 识别大幅调仓但相对市场效果不佳的操作。
- 请求用户补充少量交易记录之外的投资逻辑。

AI 不可以：

- 保存复盘注释到确定性报告。
- 确认转仓或修改交易分类。
- 覆盖成交价格、数量、日期或方向。
- 用自然语言结论回写任何计算输入。

## 失败与降级

只有查询参数无效、账户不存在或数据库读取失败导致整次请求失败。以下问题都只影响对应字段：

- 股票期末价格缺失。
- 市场基准端点缺失。
- 汇率缺失。
- 操作前组合资产快照缺失。

报告仍返回可用的原始操作事实，不产生旧版“阻断”“降级”或“不可用”全局状态，也不因为缺少交易日历尝试纠正日期。

## 测试策略

### 原始事实边界

- 在测试数据库中预置与原始交易冲突的旧纠错记录，证明轻量结果完全不受影响。
- 覆盖建仓、加仓、减仓和清仓，以及同日同方向成交合并。
- 覆盖非买卖记录不生成操作。
- 覆盖查询开始日前交易参与持仓重放、但不进入本期操作列表。

### 计算与降级

- 保留价格效果、相对市场效果、仓位影响和多币种测试。
- 验证单项行情、基准、汇率或快照缺失时其他字段仍可用。
- 验证新股只使用真实存在的上市后行情，不构造上市前价格。

### 入口与删除审计

- 后端测试确认只读 AI 工具与页面消费同一轻量服务。
- 前端测试确认页面不再引用旧状态管理、组件和类型。
- 源码检索确认旧命令名、旧服务模块、纠错表访问和 AI 写入工具没有可执行引用。
- 新建数据库模式测试确认不要求旧复盘表。
- Rust 测试、前端测试、Rust 编译检查和前端生产构建全部通过。

删除旧测试会使测试总数减少；验收依据是保留功能的行为覆盖和全套验证通过，而不是维持原测试数量。

## 验收标准

1. 股票操作复盘的每项确定性结果都能追溯到原始交易记录、只读行情、汇率或组合快照。
2. 代码库中没有读取或写入旧纠错、注释和交易日历表的运行时代码。
3. 旧复杂引擎、旧前端组件、旧命令、旧类型和专属测试已删除。
4. 轻量页面、股票排行、操作明细和 AI 只读深度复盘保持可用。
5. 已存在的旧数据库表不会影响结果，也不会在升级时被自动删除。
6. 绩效分析、期权操作复盘和其他复盘功能没有行为回归。
7. 全套自动化测试与生产构建通过，源码删除审计无残留。

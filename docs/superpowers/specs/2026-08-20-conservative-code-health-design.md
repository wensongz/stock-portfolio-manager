# 保守代码治理设计

## 目标

在不改变产品功能、行情刷新策略或模块边界的前提下，修复已证实的数据校验缺口，并删除与实际行为不一致的设置和无消费者状态。

## 已确认的项目不变量

- `symbol` 在整个应用中全局唯一，因此现有按 `symbol` 聚合和缓存的逻辑保持不变。
- 行情采用“启动时同步缓存 + 用户手动刷新”，本轮不引入周期性网络刷新。
- 不升级依赖，不拆分大文件，不调整数据库结构，不处理全局异步请求竞态。
- 保留用户现有的 `src-tauri/Cargo.lock` 修改，不纳入本轮提交。

## 改动范围

### 1. 持仓平均成本校验

`create_holding` 和 `update_holding` 目前只校验股数，没有拒绝负数或非有限的 `avg_cost`。负成本会直接污染持仓成本、盈亏、绩效和快照计算。

- 扩展 Rust 持仓校验，使 `avg_cost` 必须是大于等于零的有限数。
- 在持仓表单的平均成本输入框增加 `min={0}`，提供即时前端约束。
- 先添加覆盖负数和非有限平均成本的 Rust 单元测试，再实现校验。

### 2. 删除无效的自动刷新设置

设置页当前声称自动刷新间隔会立即生效，但行情仓库没有周期定时器，实际策略是启动同步和手动刷新。

- 删除设置页的自动刷新频率卡片、选项、处理函数和恢复出厂时的相关写入。
- 从前端持久化键列表中删除 `quote_refresh_interval_ms`。
- 从行情仓库删除刷新间隔的加载、存储和状态字段。
- 不新增定时器，不改变现有网络请求频率。

### 3. 精简行情状态仓库

静态引用检查确认以下状态或方法没有仓库外消费者：`quotes`、`fetchQuotes`、`warning`、`error`。

- 删除这些字段、实现及不再需要的 `StockQuote` 类型导入。
- 将仅负责加载缓存并监听后端刷新事件的 `startAutoRefresh` 重命名为 `startQuoteSync`。
- 更新持仓页调用点和相关注释；保留 `holdingQuotes`、加载状态、告警横幅和最后更新时间行为。

### 4. Rust 测试代码精简

- 将 Clippy 指出的 `.err().expect(...)` 改为 `expect_err(...)`。
- 此项只消除严格静态检查告警，不改变生产行为。

## 错误处理

- 后端校验失败继续通过现有 Tauri `Result<_, String>` 返回给前端。
- 使用明确错误信息说明平均成本必须是非负有限数。
- 不改变其他持仓字段或交易数据的校验语义。

## 验证

- 新增校验测试必须先因缺少校验而失败，再在实现后通过。
- 运行现有 Node 测试。
- 运行 `npx tsc --noEmit --noUnusedLocals --noUnusedParameters`。
- 运行 `npm run build`。
- 运行 `cargo test`。
- 运行 `cargo clippy --all-targets --all-features -- -D warnings`。
- 检查最终 diff，确认没有修改 `symbol` 聚合逻辑，也没有把用户的 `Cargo.lock` 改动纳入本轮提交。

# Quarterly Consistency Implementation Plan

**Goal:** 统一季度现金与币种口径，并使历史汇率不受日度缓存清理影响。

**Architecture:** 在现有重建流程中接入独立汇率存档与现金重建；持仓明细新增实际币种，报告按各季度自己的汇率生成 USD 汇总。

**Tech Stack:** Rust / rusqlite / SQLite、React / TypeScript。

**Spec:** [设计说明](../specs/2026-09-07-quarterly-consistency-design.md)

## 约束

- 在当前工作区实施，不自动提交；测试不访问用户数据库或外部行情。
- 保存原币明细、带日期和来源的汇率、季度和持仓笔记。
- 数据缺失不得伪造现金基准或汇率；失败不得覆盖旧报告。

## 实现与验证

- [x] 汇率存档与迁移：先验证清理日度缓存后仍可读历史汇率、已有季度优先、未来汇率不能用于新建过去季度；新增 v8 迁移，在 v7 清理前抢救旧记录，保存实时汇率时同步存档。
- [x] 季度重建：先复现现金遗漏；按截止日还原现金，持久化实际币种，重建时保留备注和决策评价；验证纯现金、负余额、未来交易和失败回滚。
- [x] 季度汇总：先复现混币相加；统一比较和趋势的市场/分类 USD 汇总，验证不同季度汇率、现金计数和错误传播。
- [x] 前端：按实际币种显示明细，为比较和趋势标明 USD，处理缺失汇率与负现金图形，验证数值转换和构建。
- [x] 集成：检查迁移、缓存清理、重复重建与批次撤销的交互；独立审查完整差异，运行前后端测试、构建、格式和 Clippy。

# P0 财务读模型错误语义设计

## 背景

多个仪表盘、统计、季度和 AI 读取路径在汇率服务失败后构造 `7.2/7.8`，并把时间标记为当前时间；另一些查询通过 `.ok()`、`filter_map(Result::ok)` 或 `unwrap_or(0)` 把 SQL、字段类型和日期错误解释成“没有数据”或零。这会生成看似完整、实际不可验证的财务结果。

## 目标

- 删除生产代码中的硬编码汇率回退。
- 只有 SQLite 的 `QueryReturnedNoRows` 表示可选值缺失；其他数据库错误必须传播。
- 跨币种金额接口在没有可靠汇率时明确失败。
- AI 上下文和市场概览等 best-effort 接口可以省略受影响区块，但必须用 `null` 或“不可用”表达，不得伪造数字。
- 季度趋势用批量分组查询取代分类乘季度的 N+1 查询，同时传播解码错误。

## 非目标

- 不改变汇率服务的网络供应商、缓存 TTL 或持久化格式。
- 不改变收益率、盈亏、波动率等公式。
- 不把所有业务上的合法零值改成可选值。
- 不清洗或重写用户现有数据库中的历史记录。

## 设计

### 统一汇率边界

`get_cached_rates` 保持唯一的生产汇率入口，并继续支持陈旧内存缓存和数据库缓存。修复数据库缓存读取，使“无记录”返回 `None`，字段类型或 SQL 错误返回 `Err`；当网络失败且数据库缓存读取也失败时，返回同时包含网络和持久化错误的诊断。

仪表盘、持仓排序、统计页、分类统计、AI 工具和季度当前快照直接传播 `get_cached_rates` 的错误。它们不能构造常量汇率。

AI 投资组合上下文在汇率不可用时仍可提供原币持仓和非金额信息，但跨币种总览明确输出“汇率不可用，已省略”。市场概览保留指数数据和持仓数量，将 USD 日盈亏与 movers 置空，并记录不可用原因。

### 可选查询

使用 `rusqlite::OptionalExtension::optional()` 实现真正的可选单行查询：汇率缓存、行情刷新时间、绩效基线和分类读取。获取到字符串日期后单独解析，解析失败必须返回错误。

不存在分类仍保持现有“未分类”业务行为；只有 `QueryReturnedNoRows` 可以进入该分支。

### 季度趋势

一次读取快照，一次按 `(quarterly_snapshot_id, category_name)` 聚合分类市值和去重持仓数。Rust 侧通过快照 ID 到索引的映射填充向量。所有行用 `collect::<Result<...>>()` 解码，不能丢弃坏行，也不能把查询失败当零。不存在聚合行时才用业务零填充。

## 错误语义

- 没有缓存记录：`Ok(None)`。
- SQL、锁、列类型或日期错误：`Err`。
- 跨币种端点无汇率：端点失败并显示原始错误。
- best-effort AI 数据无汇率：受影响字段为空并附带不可用说明；指数等独立数据继续返回。

## 验证

测试至少覆盖：无汇率缓存与坏类型缓存的区别、无行情刷新记录与坏类型记录的区别、绩效基线无记录与坏日期的区别、分类不存在与字段错误的区别、趋势批量聚合结果、趋势坏字段传播、AI/市场概览无汇率时不产生伪造 USD 数字，以及生产代码不再存在硬编码汇率回退。

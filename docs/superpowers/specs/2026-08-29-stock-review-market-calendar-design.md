# 股票操作复盘交易日历生产同步设计

日期：2026-08-29

## 背景与根因

股票操作复盘已把交易日历作为实际 TWR、区间回撤、动作后 20/60/120 个交易日效果和 Campaign 路径指标的权威时间轴。现有数据库包含：

- `stock_market_sessions`：逐自然日的开市/休市状态；
- `stock_market_calendar_coverage`：每个市场已经完整验证的日期范围和版本。

但生产代码目前只有建表和读取能力，写入逻辑只存在于测试夹具。真实数据库没有 CN、HK、US 日历数据，因此复盘会诚实地把相关指标标为不可用。股票行情缓存与交易日历是两个独立概念：K 线缺少某个日期可能代表休市，也可能代表停牌、未上市、接口缺数或请求失败，不能直接把个股 K 线缺口当成休市。

## 目标

1. 在用户打开或刷新股票操作复盘时，零配置地为查询涉及的 CN、HK、US 市场增量构建并缓存经过验证的交易日历。
2. 使用宽基指数 K 线发现实际开市日，使用独立行情来源交叉验证，并使用交易所公布的休市安排校验工作日闭市日期。
3. 只有整个日期区间验证完整时，才发布 `encodes_closed_dates = 1` 的覆盖元数据；任何不确定性继续诚实降级。
4. 缓存更新失败时保留上一次完整版本，不破坏已经可用的复盘。
5. 将笼统的行情覆盖率补充为可定位的股票、市场和日期缺口。

## 非目标

- 本次不解决复权价、完整公司行动或影子组合分红来源，`comparable_price_only` 警告继续保留。
- 不用用户持仓个股推断市场是否开市。
- 不把单一行情提供方的缺失日期直接认定为休市。
- 不要求用户填写日历、不新增 API Key，也不新增手工日历导入界面。
- 不在运行时抓取并解析交易所 HTML/PDF；官方休市数据以版本化资源随应用发布。

## 方案选择

### 方案 A：仅使用宽基指数 K 线

优点是零配置、实现简单。缺点是单一提供方缺数时可能把正常交易日误判为休市，不满足现有“行情观测不是日历权威”的安全边界。

### 方案 B：完全内置官方日历

优点是离线稳定。缺点是每年需要维护完整交易日列表，且运行时无法发现资源录入错误或临时休市调整。

### 方案 C：指数 K 线生成 + 独立来源交叉验证 + 官方休市表校验

本设计采用方案 C。它保留零配置体验，同时要求三类证据一致后才发布完整日历：

1. 市场参考指数实际产生 K 线；
2. 版本化官方休市/特殊闭市资源能够解释所有工作日闭市日期；
3. 第二行情来源可用时返回相同的交易日期集合；若发生冲突则拒绝发布。

## 数据来源与市场映射

每个市场配置两个逻辑参考指数，具体提供方代码封装在适配器内部：

| 市场 | 参考指数一 | 参考指数二 | 官方校验来源 |
|---|---|---|---|
| CN | 上证综指 | 深证成指 | 上交所、深交所年度休市安排 |
| HK | 恒生指数 | 恒生国企指数 | HKEX 年度交易及运营日历 |
| US | 标普 500 | 纳斯达克综合指数 | NYSE/Nasdaq 年度休市安排 |

运行时优先复用项目已有的雪球、东方财富和 Yahoo 历史行情能力。一个成功提供方只有在官方休市资源覆盖整个范围、所有预期开市工作日都有参考指数 K 线时才足以发布；第二独立提供方可用时必须交叉验证。同一提供方的两个指数用于避免指数自身异常，不能解释缺少的正常工作日。

版本化休市资源首版覆盖 2025 年至当前已经由交易所正式公布的年份，后续按年度增加。查询超出资源覆盖范围时只发布已验证交集，超出部分继续显示 `market_calendar_unavailable`，不得猜测未来节假日。

官方参考：

- 上海证券交易所：https://www.sse.com.cn/disclosure/dealinstruc/closed/
- 深圳证券交易所：https://www.szse.cn/disclosure/notice/general/
- 香港交易所：https://www.hkex.com.hk/News/HKEX-Calendar/Subscribe-to-the-HKEX-Calendar?sc_lang=en
- NYSE：https://www.nyse.com/trade/hours-calendars

## 核心组件

### `stock_review_calendar` 服务

新增独立服务模块，职责限定为：

- 计算市场本地“最近完整收盘日”；
- 读取内置休市资源；
- 通过注入的行情适配器获取参考指数交易日期；
- 校验来源一致性和日期范围完整性；
- 生成逐自然日的 `is_session` 结果；
- 原子发布会话行与覆盖元数据；
- 返回结构化同步结果和异常原因。

金融指标服务只读取已发布缓存，不直接访问网络，也不自己推断交易日。

### 行情适配器

提供统一的异步接口：输入逻辑参考指数、市场和起止日期，输出排序去重后的市场本地日期，以及提供方、实际请求边界和响应完整性信息。

适配器必须：

- 使用市场本地日期转换时间戳；
- 识别空数据、截断响应、认证失败和不支持的指数代码；
- 不把失败转换为空的“正常日期集合”；
- 保留雪球、东方财富、Yahoo 的实际来源名称，便于审计。

### 版本化休市资源

资源只记录工作日休市和特殊闭市日期；周末由确定性规则生成。每个市场、年份包含：

- 来源 URL；
- 公告或资源版本；
- 覆盖年份；
- 工作日休市日期；
- 临时闭市覆盖项；
- 数据修订标识。

资源加载失败、日期重复、日期不属于目标年份或与周末规则冲突时，整个市场年份不可发布。

## 同步与验证流程

1. 根据查询、最早相关交易日、TWR 基线需要和动作观察窗口确定所需起点。
2. 终点取各市场最近已经完整收盘的本地日期；不在盘中推断当天状态，也不生成尚未正式公布的未来交易日。
3. 读取现有覆盖。若已完整覆盖所需范围且资源版本未变化，直接复用。
4. 对缺失的前段或后段范围，获取两个参考指数的日期集合；优先获取第二独立行情提供方用于交叉验证。
5. 将所有返回日期标准化为市场本地日期，排序、去重并限制在请求范围。
6. 验证以下不变量：
   - 至少一个提供方的两个参考指数请求明确成功且没有截断；
   - 第二独立来源可用时，对开市日期集合必须一致；不可用时记录降级来源，但不能放宽官方休市与预期开市日校验；
   - 周末不得出现普通日 K 线；
   - 官方休市日期不得出现普通日 K 线；
   - 每个非周末、非官方休市的日期必须存在参考指数 K 线；
   - 结果至少包含请求范围内一个交易日，且边界可以由完整响应证明。
7. 验证成功后生成范围内每一个自然日：交易日写 `is_session = 1`，周末和已验证休市日写 `is_session = 0`。
8. 在一个 SQLite 事务中替换目标范围并更新覆盖元数据。`revision` 由资源版本、提供方、参考指数和日期集合的稳定摘要组成。
9. 提交后重新读取缓存；报告计算继续使用现有 `load_market_sessions` 接口。

## 原子性、并发与失败策略

- 新版本未完整验证前不得删除旧缓存。
- 会话行与覆盖元数据必须在同一事务提交。
- 同一市场的并发同步以市场级互斥或数据库版本比较串行化。
- 同步过程中若用户交易、行情缓存或日历修订发生变化，报告沿用现有候选修订校验重新准备，不混合两个版本。
- 来源不一致、网络失败或资源超范围时：
  - 有旧的完整覆盖：继续使用旧覆盖，并增加“日历刷新失败/版本陈旧”警告；
  - 没有旧覆盖：保留 `market_calendar_unavailable` 阻断项；
  - 绝不把部分结果发布为完整日历。

## 股票复盘集成

实时报告准备顺序调整为：

1. 根据查询和证券身份确定涉及市场；
2. 为这些市场执行日历增量同步；
3. 重新读取权威日历缓存；
4. 再准备股票行情、基准、汇率、实际 NAV、影子组合和 Campaign 输入；
5. 生成报告并执行现有候选修订一致性检查。

只同步查询真正涉及的市场。筛选为单一市场时，不因其他市场没有日历而产生阻断项。

## 行情覆盖缺口诊断

现有 `market_data_coverage` 数值算法保持不变，但新增结构化问题：

- `market_price_gap`：包含 `affected_symbol`、`affected_date` 和市场；
- 按市场、日期、标准化证券代码稳定排序；
- 页面最多展示前 20 项，并显示剩余省略数量；
- 94.4% 等覆盖率旁增加“查看缺口”入口；
- 非交易日不参与缺口分母，也不得产生缺口问题。

该诊断只解释覆盖率，不在前端补值，也不改变 Rust 的金融结果。

## UI 行为

- 首次缺少日历时，复盘页显示“正在同步交易日历”，不要求用户填写信息。
- 同步成功后使用返回的新报告刷新页面。
- 同步失败时沿用现有数据质量区域展示具体来源、市场和失败原因。
- 已有可用报告在刷新失败时继续保留；Campaign 和纠错入口仍绑定可见报告身份。
- 不增加设置页 API Key 或日历维护表单。

## 测试策略

所有实现遵循 RED → GREEN：

### 日历纯逻辑测试

- 周末、官方休市日和正常工作日分类；
- CN/HK/US 市场本地日期和最近完整收盘日；
- 两个独立来源完全一致时发布完整日历；
- 来源少一天、多一天、截断或失败时拒绝发布；
- 官方休市日出现 K 线、普通工作日缺 K 线时拒绝发布；
- 资源超范围、格式错误和修订变化；
- 稳定 revision 与输入顺序无关。

### 持久化测试

- 逐自然日写入及 `encodes_closed_dates = 1`；
- 会话行和覆盖元数据原子提交；
- 失败保留旧版本；
- 前后增量扩展与幂等重跑；
- 并发同步不会产生混合版本。

### 报告集成测试

- 空日历数据库首次报告会同步并解锁实际 TWR、Campaign 和精确观察窗口；
- 单市场查询只同步单一市场；
- 网络失败且无旧缓存继续诚实不可用；
- 网络失败但旧覆盖完整时继续计算并显示刷新警告；
- 非交易日快照和个股停牌不改变市场日历；
- 94.4% 覆盖场景返回精确缺失证券和日期；
- 日历变更参与候选修订，不能与旧行情/纠错候选混合。

### 全量回归

- 全部 Rust 测试；
- 全部 Node 视图模型、Store 和 AI 预填测试；
- TypeScript/Vite 生产构建；
- Cargo check/build；
- 有界 Tauri 启动，并明确验证只发生幂等日历缓存写入，不改动交易、持仓、注释或纠错数据。

## 完成标准

1. 当前真实数据库在首次刷新后自动获得查询所需的 CN/HK/US 完整日历覆盖。
2. 不再因为空日历表出现三个 `market_calendar_unavailable` 阻断项。
3. 日历来源异常时不会制造交易日，也不会覆盖已有完整缓存。
4. 94.4% 等行情覆盖率可以定位到具体证券和交易日期。
5. 复权价/分红不足仍明确显示价格收益降级，不被本修复掩盖。
6. 新增测试和现有全量测试通过，生产构建成功，工作区无运行时缓存或用户数据改动。
